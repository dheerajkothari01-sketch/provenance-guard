Requires Python 3.10+.

```bash
git clone <repository-url> && cd provenance-guard
pip install -r requirements.txt

# 1. regenerate the test dataset (deterministic, seed 47)
```

## 3. Detection rules

Scored on bank-detail changes only (bank account, IFSC, IBAN, SWIFT, beneficiary, payee). Points add up, capped at 100. **HOLD at ≥ 60, REVIEW at ≥ 30, else ALLOW.** The largest single rule is 40, so at least two independent signals must agree before money is held.

| Rule | Points |
| --- | --- |
| No approval reference on a bank-detail change | 40 |
| Changed by software (API key), not by a person | 10 |
| Request came from outside the key's expected network | 25 |
| Staff change made from outside the office network | 10 |
| Key has little or no history of approved bank changes | 20 |
| Close to a payment run | 15 |
| Within a week of a payment run | 5 |
| Matches an outside-company indicator (E17) | 30 |
| Same new account given to more than one vendor | 20 |
| API call for this change is missing from the log | 10 |
| Key is not allowed to change vendor records, or is disabled (E04) | 30 |
| Staff sign-in before this change looked risky (E03) | 25 |
| Vendor's phone number changed shortly before this bank change | 20 |

## 7. Known limitations

- **Forged approval references** are not checked against an approval register (none supplied). A forged reference from the expected network scores low and is sent to REVIEW, not HOLD (chg in section 5).
- **Stolen staff login with a forged approval** reaches REVIEW (35), not HOLD; it relies on E03 showing a new device, new city, MFA problem or failed attempts.
- **Business-email compromise** where a deceived manager approves the change scores REVIEW; the protection is the call-back to the phone number on file *before* any recent change, which the app displays.
- **Learned networks can be poisoned** by an attacker who sends more than 5% of a key's traffic from a new range (about 65 calls for TallyBridge's key in this data).
- **Weights are expert-set**, not statistically fitted. With few labelled cases, rates have wide uncertainty.
- **Test data is ours.** Variations were designed to dodge simple rules, but real validation needs the supplied evidence or labelled history.
- **Log quality:** LedgerOne keeps API logs for 90 days; BlueVault's clock is unsynchronised; E15 labels and E17 indicators come from the breached party and are unverified.
- **Scope:** vendor bank-detail changes only. Data theft through exports (E02) is detected by the case evidence, not by this tool.
- **Demo-grade sign-in:** salted PBKDF2 hashes, no lockout; audit log is append-only but not tamper-proof. Production would use company SSO with MFA and tamper-evident logging.
